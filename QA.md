# Verification record

Local verification performed on macOS using Node.js **22.20.0**, installed Google Chrome in headless mode, and Playwright Core **1.56.1**. Runtime dependencies loaded from their pinned external URLs. Browser QA used a static server at `http://127.0.0.1:5500`. Synthetic camera tests used generated 640 × 480 video; they did not access a physical webcam.

## Verified locally

- **54 Node tests passed** for pure geometry, both gesture modes/demos, reference ownership and side selection, zoom/palettes, face geometry, coordinate transforms, and the application lifecycle. Added application tests cover late-start cancellation, demo replacement, graphics disposal, sustained quality adaptation, stale camera frames, optional face allocation and inference fairness. Negative architecture fixtures reject domain-to-renderer imports and direct browser APIs in application code; asset tests verify deterministic revisions and detection of new modules.
- `node --check` passed for every application/test/helper JavaScript module via `npm run check`. The same command enforces domain/application import boundaries and checks that all 21 application modules share the generated browser revision.
- Actual WebGL 2 scene and GLSL materials rendered in Chrome without shader errors or uncaught runtime errors during the demo.
- Startup regression checks substitute obsolete responses for unversioned application modules. The page bypasses those URLs, loads matching versioned modules (including the lazy face renderer), and initializes correctly after reload. Generated-camera startup still reaches LIVE. This covers the missing `containTransform` export error caused by mixing script revisions.
- Full scripted cycle reached PINCH, OPEN, TWO_HANDS, FIST, HOLD, and IDLE, with the HUD explicitly identifying scripted animation.
- The new reference demo reached FIST, OPEN, PINCH, ZOOM, HOLD and IDLE. Deterministic browser hand fixtures verified visible fist-held nested shells, measured radius increase from a wider thumb-index gap, all four secondary-hand palettes without recentering, exactly one held-open release, reformation, left/right acquisition, fullscreen and mirror alignment. The reference outer radius is capped to 48% of the shorter stage dimension. [Reference QA results](references/analysis/reference-qa.json) record this separate pass.
- Both supplied recordings were visually compared, and real pinned Hand Landmarker inference sampled 102 reference frames and 269 new-recording frames at 10 Hz from local camera crops. The same detections were replayed through both interaction modes. This is recorded-video analysis, not a physical webcam session or pixel-accurate reconstruction. See [the comparison](references/COMPARISON.md), its evidence and limitations.
- Real quality changes verified: 4,500 shell points on High versus 2,000 on Low, and 3,000 ring points on Low. Brightness and mirror controls functioned.
- Normal, Bright, and Ultra bright modes were compared using actual rendered pixel light output at the same slider setting; each brighter mode increased it. The 200% slider endpoint was checked. All buttons, inputs, selectors and status elements were geometrically verified below the camera panel on desktop and mobile.
- A generated 4:3 camera stream and deterministic synthetic pinch landmarks verified panel-local anchoring after wide/narrow resizing, both mirror settings, fullscreen, scrolling to the settings, and PNG export dimensions. This checks application mapping without claiming physical hand-tracking accuracy.
- Local PNG download completed and was inspected as an image. Camera frames are composited using the same contain/mirror mapping, although physical-camera PNG alignment remains a manual check.
- Camera capture constraints request ideal 1280 × 720, while the actual-resolution label correctly reports the generated 640 × 480 stream and resets to Off after Stop. The preview maintains 16:9 on desktop/mobile. The real Fullscreen API expands only the camera stage to viewport dimensions and restores the normal layout on exit; all controls remain outside the stage.
- Wide 1440 × 1000 and narrow 390 × 844 layouts are checked for horizontal overflow. The camera occupies its own panel, with every control and the status HUD below it. Shorter windows scroll through settings without placing them over the webcam.
- Camera denied, absent, and busy errors were simulated and produced actionable messages. WebGL 2 unavailability, blocked Three.js download, and blocked model download were simulated; readable controls/error UI remained available. Model failure released the generated stream.
- The **real pinned MediaPipe model** initialized with the GPU delegate and processed generated video. A forced GPU initialization error exercised successful **real CPU model fallback**. Both paths reported zero hands on the generated geometric input, as expected; video time advanced, and Stop ended every synthetic track.
- All 307 decoded reference frames were inspected as contact sheets, with full-size first/flare/large/last-visible/actual-last frame checks and a per-frame qualitative observation CSV.
- Face shader checks use a deliberately artificial face with known skin/eye/lip pixels and generated fine lines. They verify iris-only navy recolouring, pupil/catchlight/sclera/lip/background preservation, blink suppression, luminance brightening with preserved skin channel ratios, and reduced fine-line contrast. This is algorithm verification, not a claim of photographic realism on every face.
- Rendered-pixel tone checks verify progressive lightening with strength, distinguish warmer Pearl from cooler Porcelain, retain generated fine-line contrast when smoothing is off, and preserve eye/lip/background pixels. Original tone bypasses the additional lightening pass. The available tones and measured samples are recorded in the face QA report.
- Face effects were checked through wide/narrow resizing, mirror toggles, head roll, original-view bypass, face loss/reacquisition, disable during model loading, simulated face-model failure, and Stop cleanup. Disabling/failing face effects leaves the raw webcam and hand pipeline available. Controls remain below the camera panel.
- Portrait camera-only fullscreen preserves navy iris placement and produces the expected dark letterbox pixels instead of stretching camera edge pixels across the bars.
- The **real pinned Face Landmarker** returned 478 landmarks on sampled frames of the local reference clip with GPU inference and with real CPU inference after a forced GPU initialization error. The model was closed after each run. No physical webcam was used.

[Browser QA machine-readable results](references/analysis/browser-qa.json), [hand vision QA results](references/analysis/vision-qa.json), and [face QA results](references/analysis/face-qa.json) record the test conditions. ## Not yet verified with hardware

- Real hand recognition accuracy, fingertip attachment, hand identity through crossings, and perceived response latency on a physical webcam.
- Physical-camera face retouch appearance and iris alignment across users, skin tones, glasses, contact lenses, fast gaze/head movements, extreme profiles and occlusions. The retouch mask is landmark-based, not per-pixel skin or occlusion segmentation; subjective realism remains unverified on hardware.
- Calibration across hand sizes, oblique palm orientations, darker/lighter environments, 16:9 versus 4:3 physical cameras, and different laptops. Geometry for both aspect ratios is unit tested; actual hardware alignment remains unobserved.
- Fullscreen behavior and permission prompts in every macOS Chrome/window configuration. The handler calls the real Fullscreen API and reports refusal.
- Camera unplug/reconnect behavior and prolonged GPU context-loss recovery on physical hardware.
- A sustained real-camera 30+ FPS claim. No such performance guarantee is made.
- Exact pixel fidelity to the supplied clip. The reference lacks provable gesture causality and is a recording with browser/editor chrome.

## Manual acceptance pass

1. Serve the extracted folder, open current Chrome, keep Match reference video selected, enable camera, and allow access. Confirm LIVE and GPU or CPU in the HUD. Raise one fist first, or select its displayed starting side.
2. Enable landmarks; hold the fist, pinch thumb/index, move across each corner, resize wide/narrow, and switch mirror. Confirm the nested globe follows knuckles/fingertips. Repeat with 16:9 and 4:3 camera settings if available.
3. Spread thumb and index with other fingers folded; close the gap again and roll the wrist. Confirm continuous scale changes and ring tilt while the center stays attached to the controlling hand.
4. On the other hand show 1/2/3/4 fingers; confirm ivory/cyan/violet/gold and no recentering over the face. Close the other fist; its last colour should hold. Open the controlling palm: one flash, no repeats during sustained OPEN.
5. Close/pinch to reform; hide hands; reappear. Confirm short HOLD, fade, recovery and no stale release. Change starting side explicitly and confirm the selected displayed hand acquires control.
6. Check the actual CAMERA resolution beneath the preview; compare it with the requested 1280 × 720. Set Low quality and low intensity, click Fullscreen, then press Esc to return and save a PNG. Confirm the full camera frame and mirror setting match the exported image. Stop and confirm the resolution label reads Off and Chrome's camera indicator turns off.
7. Enable Face Studio with the live camera. Adjust wrinkle reduction, skin brightening and navy-blue iris strength separately. Try the skin whitening tones and vary tone strength from zero to full; compare shadows, highlights, texture, and warm/cool undertones. Blink, turn/tilt your head, change gaze, resize and toggle mirror. Confirm the eye effect stays within the visible iris, hides on closed eyes/face loss, and recovers. Compare with Show original; verify saved PNGs contain the selected retouch. Repeat with glasses and different lighting, using moderate strengths.
8. Switch to Classic two-hand controls. Confirm pinch summons, fist collapses, two matching active hands scale at their midpoint, and the guide/hint describe this mapping. Switch back and confirm prior ownership/bursts are reset.

## Reproduce developer browser tests

Start a local static server, install Playwright Core in a separate development environment, and pass its absolute `index.mjs` path to [browser-qa.mjs](tools/browser-qa.mjs) and [vision-qa.mjs](tools/vision-qa.mjs). The scripts default to the standard installed macOS Chrome path; edit that path for another platform. These optional tools are not required to run the application.

Run the GPU browser scripts one at a time. Concurrent headless runs produced timing-dependent failures in hand-ID and face-pixel snapshots; the isolated reference pass completed successfully. These checks exercise strict frame-timing/staleness limits and do not establish performance under competing GPU loads or across system sleep.
